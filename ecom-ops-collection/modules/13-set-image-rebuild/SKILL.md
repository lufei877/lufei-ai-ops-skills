# 套图复刻

版本 v0.1（草稿）· 2026-11-26。

## 什么时候用 / 不管什么

用户有一套参考图和自己商品的实拍图，要做一套**版式一致、商品和文案都是自己的**新图：主图、SKU 图、详情图都可以。

只借版式：每张图放什么信息、文字放哪、商品占多大、画面怎么分区。场景、人物动作、道具、光线都要为新商品重新设计，文字全部重写。

不管：
- 把竞品的图、品牌、商标、人物脸、原文案原样搬过来（见 `references/借与不借.md`）。
- 编造检测报告、证书、销量、对比效果。
- 单张修图抠图、视频、没有商品实拍图的"凭空出图"。

## 先读

1. `_shared/底座规则.md`、`_shared/输出规范.md`、`_shared/提问规范.md`。
2. 用户工作目录 `店铺资料/商品档案-<商品名>.md`：第 1 栏规格、第 3 栏卖点和证据、第 5 栏不能说的。有 `10-review-mining` 的交接卡就一起读，买家在意的点优先上图。
3. `references/逐图设计卡.md`、`references/提示词写法.md`、`references/验收与返修.md`。

## 步骤

1. **收材料**：参考图由用户自己保存后给出，一张一个文件；不登录别人的账号去抓，也不叫用户交出登录信息。再要新商品实拍图（越多角度越好）。没有实拍图就停下，说明原因，不用参考图里的商品凑数。
2. **问缺的**：只问档案没有的，一次最多 3 个——要做几张、哪个平台和尺寸、有没有必须出现的资料（规格表、包装标签）。
3. **先出计划**（底座规则第 3 条）：每张新图对应哪张参考图、用哪几张商品图、先试哪一张、做完交什么。用户确认再动手。
4. **拆参考图**：每张写一张设计卡（格式见 `references/逐图设计卡.md`），把版式锁成文字：文字块的数量、类型、位置、层级，商品占比，画面分区，色系。看不清的写"看不清"，不猜。
5. **换内容**：文案从商品档案出，每条标出自哪一栏；档案没有证据的卖点不写成肯定句，标 ？待补。文字块装不下就改文案，不挪、不放大文字块。
6. **先试一张**：挑版式最复杂的一张生成，按验收表检查，通过再做其余；不通过先改规则和提示词，别急着批量。
7. **逐张生成**：一次一张，提示词按 `references/提示词写法.md` 写。每张记下实际用的提示词、传了哪几张图、用的什么生图工具、第几版。
8. **验收返修**：逐张按 `references/验收与返修.md` 检查。先修版式再修局部，每次改动存新版本；同一处连续两轮修不好就停，查原因，仍不行如实标"未通过"，不宣称复刻成功。
9. **交付**：对照页、图片、交接卡，见下。完成后逐条自检。

## 做完的标准

- 每张新图都有对应的参考图、设计卡、实际用的提示词和检查结果，能追溯。
- 每张图的版式检查（文字块数量和位置、商品占比、分区）逐项有结论，不是一句"看起来一致"。
- 图里没有竞品的品牌、商标、优惠、参数、人物脸；商品外形、包装、标签和实拍一致。
- 图上每个数字和卖点都能在商品档案里找到出处；没证据的没写成肯定句。
- 结果标清楚：通过、带偏差接受（写偏差是什么）、未通过（写卡在哪），没有把未通过说成通过。

## 输出

交付目录只放 3 样：

1. `<商品简称>-套图对照.html`：单文件，不依赖外网，手机 390px 不横向滚动。每张一屏：参考图｜新图｜检查结果｜实际提示词（折叠）。顶部先写结果汇总：几张通过、几张带偏差、几张未通过。页脚小字只写"路飞的AI运营笔记"。图片放同级 `图/`，用相对路径。
2. `图/`：新图最终版，文件名 `<序号>-<主图或SKU或详情>.png`；`图/过程/` 放各版本和参考图。
3. `交接卡.md`：给后续模块读。写：做了哪些图、状态、没通过的点、提示词清单位置、用过的商品图。

示例：`references/示例/`（一张主图从设计卡到两轮返修的完整记录，和对照页样子；商品图来自 CC0 图库，卖点和店铺都是示例）。

## 和别的模块

- 卖点不够硬，先跑 `10-review-mining`，再回来做图。
- 只要主图的构图建议、不出图：用 `03`；批量判断保留还是重做：用 `05`；拆一批现成套图找共性：用 `06`。这三个目前写的是抖店宠物类目，通用部分可参考。
