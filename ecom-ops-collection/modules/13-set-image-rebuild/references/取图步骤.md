# 取图步骤（从链接取参考图）

> v0.1 · 2026-11-26。**还没在真实商品页实测**。天猫、淘宝页面结构以实际为准，取不到就让用户自己存图，别硬套。

## 前提

- 用户在自己的浏览器里已登录。Agent 不替用户登录，不要求在聊天里发账号、密码、验证码；不保存 Cookie、签名。
- 遇到滑块、验证码、限流就停手，告诉用户，由用户自己处理；不破解、不换身份、不开多个窗口加速。
- 只取页面上公开展示的图片，用来学版式，不转发、不在对外内容里原样展示。能下载不代表能搬运或商用，参考图只在本机用来拆版式。

## 要取什么

1. **主图**：商品页顶部轮播里的静态图，按页面顺序。轮播里的视频单独记一笔，不算主图。
2. **SKU 图**：展开规格选项，每个规格选项对应的图。多个规格可能共用一张图，保留"规格 → 图"的对应。
3. **详情图**：向下分段滚动详情区，等图片真的加载出来（不是占位符）再保存，每一屏切片一张。记录总数、已取到几张、失败几张；没取全不许说"全取了"。

## 怎么存

```
参考/
  主图/主图01.jpg …
  SKU/规格名-图.jpg …
  详情/详情01.jpg …
  清单.md
```

- 文件名保留页面里的原序号。重复的图只标重复，不改后面图的序号（详情 09 不能因为去重变成详情 08）。
- 尺寸从文件里读，不用网页上显示的大小。
- 清单.md 一行一张：序号、类别、来源链接里的商品 id、取到的日期、宽×高、是否取到。取不到写原因，不补造地址。

## 三种取法（按推荐顺序）

> 下面第 1、2 种的依据是对一款现成插件的静态分析（只看代码，没有真跑过），页面改版就会变，以真实页面为准。

1. **用户自己装的下载类插件**（如店透视的"图片下载"）：用户在商品页点下载，得到一个 ZIP（主图、SKU 图、详情图分开命名，另可出详情长图）。把 ZIP 解压成上面的目录就行。最稳，第一次真跑建议走这条。
   - ZIP 生成成功不等于每张图都下成了；有失败时 ZIP 里会附一份"请自行下载"的清单，要检查。
   - 逐张打开确认能解码，不是登录页或错误页。
2. **读页面里已有的数据**：商品页加载时，商品对象里已经带了主图地址和每个规格对应的图（SKU 图在规格属性值的 image 字段）。详情图在"商品描述"里：先看详情对象里指向描述的地址，判断是新结构还是旧结构；新结构的描述里有富文本图和单图模块，旧结构是一页一页的图片列表，把里面的图片地址按顺序收集起来再逐张下载。要在用户已登录的页面里执行，不另存、不转发登录信息。
3. **滚动页面收图**：打开详情区，分段向下滚动，等懒加载的图真的出来，再收集详情区里的图片地址。不依赖接口格式，但慢，容易漏图，所以必须核对数量。

三种都要：保留原序号、读文件真实尺寸、数量对不对要核；遇验证码停手，不绕过。

## 取完先检查

- 打开几张看，确认不是登录页截图、占位图、懒加载的灰块。
- 数量对不对：主图通常 5 张左右、详情几十屏，差得多就是没取全，回去补。
- 记下"这条链接的商品 id"和日期。链接换了，旧的图只留历史，不混进这一轮。

## 取不到时

让用户自己把主图、SKU 图、详情图保存下来给你，按上面的目录放好。这不丢人，比绕过验证强。
