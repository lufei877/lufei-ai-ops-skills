# 业务 UI

把重复强调的业务界面要求用于当前设计和实现。详细规范只有一个维护源：[业务 UI 模式](references/business-ui-patterns.md)；来源与置信边界见[归纳依据]。

## 何时使用

- 新增、调整或审查需要逐条比较、筛选、选择、批量操作的业务页面。
- 修改表头、列表密度、详情展开、账号上下文、异步刷新、队列状态或失败恢复。
- 用户没有重复说“像 Excel”或“表头可点击”时，仍按上述页面任务使用；不因代码包含 table、UI 或 worker 就加载。

## 执行步骤

1. 先读目标项目最新规则、UI 决定、主题与同类组件，确定本次任务的授权范围。已有组件和页面契约优先，不为套用本 Skill 换框架或依赖。
2. 开始改动前读取详细规范第 2 节默认检查和第 5 节项目差异，再按第 3 节选型读取本次相关的 UI-01 至 UI-14。详细正文不需要常驻加载到每个任务。
3. 新页面按第 6 节明确记录 ID、数据/账号范围、常显字段、排序循环、选择范围、筛选默认、刷新状态和恢复路径。小改动只补涉及的契约，不机械新建文档或追问已明确的事实。
4. 用现有组件实现当前最小闭环。交互差异遵循目标项目契约；缺少会改变业务结果的关键信息时才补问。
5. 按第 7 节选择相关验收。表头和选择用交互证明，密度与遮挡用实际界面证明；报告已执行的验证和仍缺失的层次。
6. 用户纠正稳定模式时更新对应模式及来源摘要，字段、品牌、阈值和具体像素保留在项目知识。跨项目安装与稳定发布继续走各自流程。

## 默认要求

- 同类业务记录优先一行一条，比较指标独立成列；关键判断、状态和常用动作可见。
- 可排序表头必须实际改变顺序，按原始数值排序，并声明初始顺序、方向、点击循环、恢复路径与排序范围。
- 选中状态绑定稳定 ID，表头全选范围清楚；重排不能把批量动作换到其他对象。
- 优先减少冗余间距，保护关键列、可读性和操作位置；长明细按需展开。
- 临时筛选、已保存默认、自动任务配置分别处理；账号变化和异步回填不能串对象。
- 刷新保留合理上下文，旧数据可识别，结果渐进回填；后台任务只限制冲突操作。
- 状态与进度基于真实阶段和回执，失败摘要可读，完整诊断与恢复入口可达，未知结果先核对。
- 沿用当前主题和同类组件，去掉已被替代的旧试稿；不自动添加公式、所有单元格编辑或批量粘贴。

这些默认要求不能覆盖用户最新决定。项目 A 指定表头再次点击恢复原序，项目 B指标表切换升降序；两者筛选保存、行高、账号位置和配色也有作用域差异，详见第 5 节。

## 输出契约

交付当前请求需要的设计、实现或审查结果，并提供：

- 使用的页面模式及关键行为；新页面或行为变化明确相关契约，已有事实可以引用。
- 与默认模式不同的项目决定和依据；不把归纳建议说成用户已确认的要求。
- 实际执行的验证、结果和重要缺口；源码/构建、隔离交互、真实界面、平台操作分别报告。

只有在当前任务需要时才新增设计文档、测试或依赖。不以截图代替排序与提交行为证明，不以历史要求有来源代替当前软件已实现。

## 不适用

纯后端查询、数据库 schema、Excel 工作簿生成或处理、营销落地页、文章排版和纯媒体展示不使用本 Skill。业务页面涉及的服务、安全或桌面架构按实际修改对象补充相应能力，UI 层不直连数据库。简化人工操作不扩大外部写入授权。
