# 业务 UI

## 什么时候用 / 不管什么

用于设计、实现或审查数据密集型业务界面的字段、排序、筛选、选择、异步刷新和失败恢复。现有组件和项目契约优先，避免为了套用规则换框架或依赖。

## 先读

有店铺档案就读，没有不用建。若任务涉及真实商品字段，再读相关商品档案。读取目标项目现有规则、页面决定、主题、同类组件、稳定 ID、数据范围和任务状态。缺少会改变业务结果的关键信息时按提问规范问。

## 步骤

1. 写清业务对象、稳定 ID、数据或账号范围、常显字段和状态来源。
2. 记录排序初始顺序、方向、点击循环、恢复路径、排序范围、筛选默认和选择范围。
3. 设计刷新、异步回填、重排、分页、取消、失败和重试时的对象关联。
4. 复用现有组件实现最小闭环，UI 不跨层访问数据库或平台实现。
5. 用交互证明排序、筛选和批量选择，用实际界面证明密度与遮挡。
6. 记录项目差异与依据，报告执行过的验证和缺失的验证层次。
7. 多步或动文件前先给计划，完成后逐条自检。

## 做完的标准

- 排序、筛选、分页和批量选择都绑定稳定 ID。
- 异步回填、刷新和重排不会串到其他业务对象。
- 失败、取消和未知结果都有可读状态和恢复入口。
- 已说明使用的页面模式、项目差异和实际验证。
- 没有把历史建议写成当前项目已确认事实。

## 输出

输出当前请求所需的设计、实现或审查结果，按共享输出规范分开写可直接执行内容和说明。需要时引用模块 references 中的业务 UI 模式。
