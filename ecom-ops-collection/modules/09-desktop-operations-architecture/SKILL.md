# Windows 桌面运营软件架构边界

## 什么时候用 / 不管什么

用于划分桌面 UI、service、repository、adapter、后台任务、队列、数据路径和迁移职责。重点是可恢复、可定位和按稳定业务 ID 回填。

## 先读

先读店铺档案和相关商品档案的业务对象、账号边界和操作权限。读取项目的桌面运行方式、worker、数据存储、路径服务、迁移状态、日志和凭据边界。缺少架构事实时按提问规范问，不凭通用经验补写。

## 步骤

1. 画出 UI、service、repository、adapter、worker 和持久化之间的调用边界。
2. 将显示、参数收集和状态订阅留在 UI，将业务逻辑、数据访问和平台细节分别归位。
3. 为长任务写稳定业务 ID、幂等键、时间戳、来源、错误、进度、取消和重启恢复状态。
4. 把网络、浏览器控制、文件扫描、批量计算和下载放入后台任务。
5. 检查分页、过滤、重绘、重启和迁移后状态仍关联正确对象。
6. 检查路径迁移的空目标、非空目标、锁文件、中文路径、源保留和恢复。
7. 检查凭据使用、脱敏日志、写入授权、回读验证、超时和按动作计算的重试预算。
8. 多步或动文件前先给计划，完成后逐条自检。

## 做完的标准

- 调用边界和实际受影响职责清楚。
- 长任务有状态、幂等、错误、来源和恢复路径。
- UI 仍可导航、筛选和继续提交，结果按稳定 ID 回填。
- 取消、失败和迁移失败不会变成成功或覆盖唯一数据。
- 已说明桌面运行、worker 和打包各检查了什么。

## 输出

输出架构设计或审查结果，说明职责边界、状态模型、迁移和验证。按共享输出规范标事实、推测、未知和需要用户确认的决策。
